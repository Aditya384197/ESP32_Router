# ESP32 NAT Router — High Performance Audited Baseline

Classic ESP32 / 4 MB flash.

This project keeps the proven Martin Ger APSTA + lwIP IPv4 forwarding + NAPT architecture while removing non-essential services and adding only the requested Hidden-SSID and HTTP OTA functions.

## Included

- Wi-Fi AP + STA (APSTA)
- IPv4 forwarding
- lwIP IPv4 NAPT
- DHCP for AP clients
- NVS persistence for Wi-Fi settings
- Hidden AP SSID control
- Lightweight local management page
- HTTP OTA firmware update
- OTA image target/size validation
- ESP-IDF OTA rollback support
- GPIO0 factory reset
- Minimal boot/reset diagnostics

## Removed

WireGuard/VPN, ACL/firewall processing, packet capture, per-client statistics, port forwarding, DHCP reservations, MQTT/Home Assistant, MCP, remote console, OLED, LED/LED strip, mDNS, WPA Enterprise, Wi-Fi scan subsystem, TTL/MSS/PMTU hooks, large CLI/command-history framework, Ethernet support, and unrelated targets.

## Performance profile

The Wi-Fi/TCP settings are based on Espressif's ESP32 Wi-Fi iperf profile rather than speculative values. This includes 16 static RX, 64 dynamic RX/TX, 32 RX/TX BA windows, 65534-byte TCP send/window buffers, and 64-entry TCP/UDP/TCPIP mailboxes.

The build also enables lwIP extra IRAM optimization. No `WIFI_PS_NONE` or custom NAPT/packet hook was added.

## Flash layout

The classic ESP32 partition geometry is restored to the tested Martin layout:

- bootloader: 0x1000
- partition table: 0x8000
- NVS: 0x9000
- OTA data: 0xF000
- PHY init: 0x11000
- OTA0: 0x20000, 1536 KiB
- OTA1: 0x1A0000, 1536 KiB
- storage: 0x320000, 320 KiB

Keeping the original offsets removes an unnecessary boot/partition variable from the direct-flash experiment.

## Build

ESP-IDF 5.1.2, target `esp32`:

```text
idf.py set-target esp32
idf.py build
```

The GitHub Actions workflow checks that the application fits inside the 1536 KiB OTA slot.

## Direct flash

Use the binaries generated by the **same build**. Do not mix bootloader, partition table, OTA data, and application binaries from different builds.

For a merged image, the merged binary is flashed at address `0x0`. For separate images, use the addresses listed above.
